# «Мои задачи» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the starter counter with a task list that supports adding, completing, deleting, and locally persisting tasks.

**Architecture:** Keep the UI in `lib/main.dart`, define a small serializable task model in `lib/models/task_item.dart`, and isolate SharedPreferences JSON persistence in `lib/data/task_repository.dart`. The screen loads through the repository on startup and writes the updated list after each user action.

**Tech Stack:** Flutter, Material UI (existing `material_ui`), `shared_preferences`, `flutter_test`.

**Spec:** `docs/superpowers/specs/2026-11-23-my-tasks-design.md`

## Global Constraints

- Support Android, iOS and Web according to the `mobile-web` profile.
- Store data locally only; no accounts, server or cross-device synchronization.
- Keep the interface small and clear: task input, task list, complete and delete actions.
- Do not add dates, categories, priorities or collaboration.
- Store each task with a unique identifier, text and completion status.
- Do not create empty tasks; show a helpful empty-list message and invitation.
- Run formatting, analyzer and tests; report unavailable UI checks as SKIPPED or BLOCKED.
- Do not update golden baselines without human approval.

## Review Focus

- Empty or whitespace-only input must not create a task; cover in the screen widget test.
- Task text must survive JSON round-tripping, including punctuation and non-Latin text; cover in the model test.
- A corrupted stored JSON value must not crash startup; cover in the repository test and recover as an empty list.
- Rapid repeated task actions must persist the latest list rather than stale state; cover in the screen persistence widget test.
- Narrow layouts must keep task controls usable without overflow; cover in the screen widget test at a narrow test viewport.
